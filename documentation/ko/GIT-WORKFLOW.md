# Bop It Access의 Git 작업 절차

Git은 이 프로젝트의 소스 코드와 문서 변경 기록을 보관합니다. **커밋**은 내용을 확인하거나 돌아갈 수 있는, 이름이 붙은 스냅샷입니다. GitHub에 이러한 커밋을 게시하면 다른 사람이 변경 사항을 읽고 직접 프로젝트를 빌드할 수 있습니다. 커밋한다고 해서 공개 릴리스가 자동으로 만들어지는 것은 아닙니다.

## 기존 기록에 관하여

`0.1.0`부터 `0.6.12`까지 처음 37개 소스 빌드는 남아 있던 소스 보관 파일과 원래 변경 메모를 사용해 각각 별도의 커밋으로 가져왔습니다. Git 시간 정보는 원래 빌드 날짜가 아니라 가져온 날짜를 기록합니다. 이후 작업은 소스 커밋에 직접 기록됩니다. 이제 Git과 GitHub가 프로젝트의 변경 기록이며, 별도의 빌드 기록 문서는 관리하지 않습니다.

커밋 작성자에는 Christopher Shaw의 GitHub no-reply 주소를 사용합니다. AI의 도움을 받은 커밋에는 실제로 기여한 모델 이름을 적은 `Co-authored-by` 줄을 포함합니다. 세션 기록에 따르면 첫 번째 과거 빌드는 GPT-6 Luna, 이후 36개는 GPT-6 Sol이 기여했습니다. 앞으로는 해당 커밋에 기여한 모델의 현재 이름을 사용하세요.

컴파일된 DLL, 설치 프로그램, 릴리스 ZIP, 생성된 게임 어셈블리, 개인 로그, 임시 빌드 결과물은 Git 소스 기록에 넣지 않습니다. 로컬 버전 태그는 자동으로 게시되지 않습니다. GitHub 릴리스 생성은 별도로 의도하여 수행하는 작업입니다.

## 유용한 명령어

저장소 폴더에서 PowerShell을 열고 다음을 실행합니다.

```powershell
git status                 # See changed, added and untracked files
git diff                   # Inspect changes that are not staged
git log --oneline           # Browse commits
git show --stat HEAD~1      # Inspect the previous commit's changed files
```

차례대로 변경·추가·추적되지 않은 파일 보기, 아직 스테이징하지 않은 변경 확인, 커밋 목록 보기, 이전 커밋에서 변경된 파일 확인을 수행합니다. 이 명령어들은 저장소를 살펴볼 뿐, 설치된 모드나 게임을 변경하지 않습니다.

## 앞으로 변경할 때마다

1. 필요한 소스와 문서를 수정합니다. 새 빌드를 만들 때는 버전도 업데이트합니다.
2. 영향을 받는 모든 번역 가이드를 업데이트합니다. 컴파일된 배포물에는 플레이어 문서와 라이선스 고지를 포함하세요. 개발자용 README와 이 작업 절차는 플레이어용 릴리스에 포함하지 않습니다.
3. 새 바이너리가 필요한 변경이면 컴파일하고 로컬 파일을 준비합니다. 게임 플레이 테스트는 요청되었을 때 실제 사람이 수행합니다. 컴파일만으로 실행 중 동작까지 검증했다고 표현하지 마세요.
4. `git status`와 `git diff`를 실행합니다. 필요한 파일을 스테이징한 다음 `git diff --cached`를 확인합니다. 생성된 바이너리, 개인 로그, 게임 참조 파일은 스테이징하는 변경에 포함하지 않습니다.
5. 내용을 잘 설명하는 커밋을 만듭니다. 제목에는 버전 번호를 넣지 않습니다. 본문에 무엇을 왜 바꿨는지 적고, 관련 확인 사항과 한계도 포함합니다. AI가 기여했다면 공동 작성자 줄에 실제 모델 이름을 적습니다.

   ```text
   Co-authored-by: MODEL NAME <noreply@openai.com>
   ```

   `MODEL NAME`을 해당 작업을 작성한 모델 이름으로 바꿉니다. 작성자는 Christopher Shaw로 유지하고, 주소는 `336230252+Chris-E-Shaw@users.noreply.github.com`을 사용합니다.
6. 변경 사항을 게시할 준비가 되면 `git push origin main`을 실행합니다. 브랜치의 커밋을 게시하지만 로컬 태그를 푸시하거나 릴리스를 만들지는 않습니다.

하나의 일관된 변경이라면 소스와 문서를 같은 커밋에 포함할 수 있습니다. 독립적인 변경을 설명할 때는 별도 커밋도 유용합니다. Git은 작업을 자동으로 업로드하지 않습니다. 다른 사람이 읽을 준비가 되었을 때 의도하여 푸시하세요.
