# Bop It Access에 대한 Git 워크플로

Git은 프로젝트의 소스 코드와 문서에 대한 변경 내역을 유지합니다. **커밋**은 검사하거나 돌아갈 수 있는 명명된 스냅샷입니다. GitHub은 이 소스 기록을 게시하여 다른 사람들이 코드를 읽고 직접 모드를 빌드할 수 있도록 합니다. 저장소에는 컴파일된 모드 파일이나 GitHub 릴리스가 포함되어 있지 않습니다.

## 기존 이력에 대해

빌드용 소스 아카이브 `v0.1.0` 통해 `v0.6.12` 37개의 연속 Git 커밋으로 가져왔습니다. 각 커밋은 해당 항목을 사용하여 소스 변경 사항을 설명합니다. [BopItAccess-build-history.html](BopItAccess-build-history.html). 이러한 커밋은 Git 가져오기 중에 생성되었으므로 Git 타임스탬프는 원래 빌드 날짜가 **아닙니다**. 주제는 버전 번호 없이 변경 사항을 설명합니다. 빌드 기록 문서는 각 버전에 속하는 소스 스냅샷을 기록합니다.

릴리스 ZIP 파일, 컴파일된 DLL 및 임시 빌드 출력은 Git의 소스 기록 외부에 유지됩니다. 빌드 기록 페이지는 해당 GitHub 소스 커밋에 연결됩니다. 기존 버전 태그는 로컬로 유지되며 초기 GitHub 게시의 일부가 아닙니다. GitHub 버전 태그 또는 릴리스가 아직 게시되지 않았습니다.

Git 커밋은 Christopher Shaw의 GitHub 무응답 주소를 작성자로 사용합니다. Codex로 작성된 커밋에는 다음도 포함됩니다. `Co-authored-by` 작업에 기여한 모델의 이름을 지정하는 예고편. 세션 기록은 첫 번째 기록 빌드에 대해 GPT-6 Luna을 식별하고 다음 36에 대해 GPT-6 Sol를 식별합니다. 이후 커밋에 대해 모델이 변경되면 해당 커밋 트레일러에서 새 이름을 사용합니다.

## 유용한 명령

이 프로젝트 디렉터리에서 PowerShell을 열고 다음을 실행합니다.

```powershell
git status                         # See changed, added, and untracked files
git diff                           # See changes that have not been staged
git log --oneline                   # Browse source commits
git show --stat HEAD~1             # See files changed in the preceding commit
```

이 명령은 저장소만 검사합니다. 모드나 설치된 게임은 변경되지 않습니다.

## 향후 빌드마다

1. 소스를 변경하고 다음 빌드 버전 번호를 선택하세요.
2. 평소처럼 모드를 빌드하고 로컬 아카이브를 준비하세요. 전체를 포함 `documentation` 모든 설치 아카이브에 영어 가이드와 모든 번역된 언어 하위 폴더가 있는 폴더입니다. 빌드를 설치할 때 해당 폴더를 게임 설치에 복사하세요. 게임 내 가이드는 모든 시작 시 현재 게임 언어에 대한 HTML을 읽습니다. 빌드가 완료된 것으로 기록하기 전에 결과를 검사하세요. 컴파일된 아카이브는 GitHub 외부에 남아 있습니다.
3. 실행 `git status` 그리고 `git diff`. 어떤 파일이 변경되었는지 확인하세요. 의도한 소스 및 문서 변경 사항을 준비한 후 다음을 사용하여 검토합니다. `git diff --cached`.
4. 제목에 버전 번호 없이 설명이 포함된 소스 커밋을 만듭니다. 포함 `Co-authored-by` Codex이 커밋을 작성할 때 실제 모델 이름이 포함된 예고편입니다. 예를 들어, `git commit -m "feat(speech): add example setting" -m "Co-authored-by: MODEL NAME <noreply@openai.com>"`; 교체하다 `MODEL NAME` 해당 커밋에 사용된 모델을 사용합니다.
5. 빌드에 대한 항목을 추가합니다. `BopItAccess-build-history.html`, 기존 커밋 스타일 형식을 사용합니다. 실제 변경 사항, 그 이유 및 관련 제한 사항을 설명하고 4단계의 소스 커밋을 연결합니다. 패키징하기 전에 해당 번역된 복사본을 업데이트합니다. 동일한 저자와 정확한 공동 저자 예고편으로 업데이트된 기록을 커밋하세요. 로컬 문서 폴더를 새로 고치고 기록 파일이 이미 복사된 경우 보관하십시오.
6. 다음을 사용하여 소스 및 기록 커밋을 모두 게시합니다. `git push origin main` 준비되면. 이렇게 하면 분기만 푸시됩니다. 로컬 버전 태그를 푸시하거나 GitHub 릴리스를 생성하지 않습니다.

빌드를 생성하지 않는 소규모 작업에는 자체 커밋이 있을 수 있습니다. 그러면 다음 빌드 커밋이 이를 따를 수 있습니다. 개인 로그, 게임 설치, 생성된 바이너리, 기타 컴퓨터 관련 파일을 커밋에서 제외하세요. GitHub 릴리스가 나중에 유용해지면 그 당시 태그와 컴파일된 다운로드를 결정하십시오.

Git은 새 작업을 자동으로 업로드하지 않습니다. 각 로컬 커밋 후에 다른 사람이 볼 수 있을 때 의도적으로 푸시하세요.
