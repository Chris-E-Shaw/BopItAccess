Bop It Access：发布准备代码审查

Mod 0.9.8 和安装程序预览版 0.1.5。于 2026 年 10 月 7 日为 Christopher Shaw 编写，为计划中的 1.0 发布做准备。

后续修正 — 2026年10月7日

本次审查后的玩家测试发现了 v0.9.8 的回归问题：重复绑定检查拒绝了有效的原生重新绑定，包括把 Bop 绑定到上方向键，以及把 Twist 绑定到新空出的空格键。构建历史中的 v0.9.9 条目记录了修正。本报告仍保留原始 v0.9.8 审查记录；编译结果并不代表已验证运行时行为。

后续记录 — 2026年10月7日：检查原生菜单事件发现 Play 按钮缺少选中状态音频监听器，同时存在视觉刷新期间重复播放选择音的路径。构建历史中的 v0.9.10 条目记录了针对性修正。仅凭语音日志无法证明实际听到的播放效果；人工音频验证仍未进行。原始 v0.9.8 审查及其编译验证限制保持不变。

范围与方法

静态审查涵盖了 Mod 和安装程序的所有 C# 源文件、卸载脚本、项目构建定义、配置模板及文档与目录编制脚本。审查考虑了所有权、关闭、并发、导航和重新绑定的状态转换、损坏文件、原生回退路径、每帧工作、重复状态检查及未使用代码。并行审查人员分别负责语音/音频/界面、输入/配置/工具及安装/恢复；协调审查人员负责路由、提示、指南导航、Mod Settings 及欢迎界面处理。集成后的修改经过了第二次源代码审查。

这是代码审查和编译记录。没有为这些修改运行游戏、安装程序操作、卸载操作、自动化测试套件或性能基准测试。先前的人工测试仍有价值，但不能证明此次重构的运行时行为。

有意保留的行为与代码

  • 自动最终分数语音保持优先级；按需重复分数仍可被打断。游戏过程中不公开分数。
  • 语音和盲文仍使用 Prism。自动模式仍依次优先选择运行中的屏幕阅读器、OneCore、SAPI。语音配置保持独立。
  • 菜单默认值、已保存偏好设置键、可编辑 INI 名称、绑定、欢迎界面关闭规则及翻译后的玩家可见字符串保持兼容。
  • 按先前要求，隐藏的 Trim Silence 实验保留在源代码中，仍不对最终用户开放。未将其视为意外遗留的无用代码。
  • 历史构建记录、保留的源代码导入及旧编制工具继续作为来源记录。对过时迁移设置启用门槛，而非悄悄删除该记录。
  • 在需要保护顺序或并发状态变化的地方，保留语音队列、原生回退检查及锁前后的重复准入检查。实现更短并不足以成为删除保护措施的理由。
  • 生成的游戏程序集及编译后的 Mod/安装程序文件仍置于 Git 之外。构建引用继续使用玩家自己的安装，并禁用复制。
  • 静态审查未确认缺陷的原生游戏时序、校准调度、分数规则及翻译措辞均未进行推测性修改。

编译与实际限制

集成后的 .NET 6 x64 Mod 0.9.8 在 Release 和 Debug 中编译，警告和错误均为 0。最终源代码修改后，Windows x64 自包含安装程序 0.1.5 发布完成，诊断为 0。编译成功不能证明运行时正确性。未为此构建运行测试、游戏、安装、卸载或基准测试。

Prism 的 P/Invoke 声明已与固定的 v0.18.3 公共 C 头文件比较。这可以发现声明不匹配，但不能证明每个原生驱动程序、屏幕阅读器、语音或盲文显示器的行为。

原生 DLL 崩溃和阻塞的驱动调用不总能在托管代码中恢复。因此关闭等待有上限，并避免从其他线程释放上下文。失败的语音批次被记录并丢弃；后续请求可继续，但失败文本不会自动重播。

部分校准回调仍在 FMOD 回调中读取原生状态。现有保护可隔离托管异常，但静态审查无法证明所有跨线程时序行为。在未经人工游戏测试的情况下改变调度可能影响校准，因此这仍是具体的后续检查领域。

指南仍是用于提供的 HTML 文档的轻量阅读器，而非通用浏览器。新的限制会有意拒绝异常庞大或深度嵌套的文档，并安全回退。Windows 拒绝访问用户配置文件时，安装程序清理可能无法完成；保留的启动器和检查点允许稍后重试。

性能修改移除了可识别的重复工作及分配。不声称帧率、延迟或内存已有测量证明的改善。发布前人工检查应涵盖原生及自定义重新绑定、打开界面输入的按住/释放、首次运行欢迎界面、所有指南表格、分数先于菜单的语音顺序、OneCore/SAPI 切换及后台行为。安装程序中止、中断恢复、共享加载器保留及偏好设置清理重试也需要在可丢弃的测试安装上检查。

本次审查未发现问题并不能保证项目没有缺陷。此构建是发布准备候选版，并非 1.0 公开发布版。

可编辑配置使用指纹和原子替换，但最后一次比较与重命名并非操作系统的 compare-and-swap：不配合的编辑器可能在这个短暂间隔内写入。强制终止可能留下唯一临时文件；卸载仅删除经过所有权验证的名称。原生游戏/Steam 偏好设置持久化可能在抛出异常前已部分写入，且没有共享事务 API。

旧手动安装没有持久所有权台账。其删除只能针对已知 Mod 文件及安全识别的依赖项，清理警告可在打开的安装程序中重试。保留的 Windows 条目/检查点路径适用于安装程序管理的副本。备份缺失、用户配置文件访问被拒绝、驱动器不可用及保守的共享加载器检测可能需要稍后重试；这些情况会被报告，而非悄悄删除归属不明的文件。

输入资源清理旨在 Unity 线程上的应用程序关闭时执行。未来若增加游戏继续运行的热卸载路径，必须先移除克隆行和提示引用，再销毁其引用的 Mod 输入资源。原生驱动调用、多控制器捕获顺序及校准回调仍需要人工运行时检查。

全部 6 个 Python 编制脚本均通过 py_compile 语法编译。PowerShell AST 解析器报告 uninstall.ps1 和 prepare_prism.ps1 的语法错误均为 0。这些检查未执行脚本功能、下载依赖项或进行安装/删除。

便携式 SDK 在文件事务之前准备。捕获到取消操作时会删除其暂存目录，但解压期间断电可能会留下这个唯一命名的目录。常规卸载会有意保留 SDK。如果旧清理辅助进程恢复运行时，新安装程序持有清理互斥锁，辅助进程会保留状态文件夹；其中的卸载完成记录允许以后重试清理。
