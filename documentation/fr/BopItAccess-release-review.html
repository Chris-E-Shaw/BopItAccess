Périmètre et méthode

La revue statique a porté sur chaque fichier source C# du mod et de l’installateur, le script de désinstallation, les définitions de compilation du projet, le modèle de configuration et les scripts de création. Elle a examiné la propriété des ressources, l’arrêt, la concurrence, les transitions de navigation et de réaffectation, les fichiers endommagés, les solutions de repli natives, le travail effectué à chaque image, les vérifications d’état répétées et le code inutilisé. Des réviseurs ont travaillé en parallèle sur la parole, l’audio et les écrans ; les entrées, la configuration et les outils ; ainsi que l’installation et la récupération. Le réviseur coordinateur a traité le routage, les indications, la navigation dans le guide, les paramètres du mod et l’accueil. Les modifications d’intégration ont fait l’objet d’une deuxième revue du code source.

Ce document consigne une revue du code et des compilations. Aucune session de jeu, opération d’installation ou de désinstallation, suite de tests automatisés ni mesure de performances n’a été exécutée pour ces modifications. Les essais humains antérieurs restent précieux, mais ne permettent pas d’établir le comportement de cette refactorisation à l’exécution.

Comportements et code volontairement conservés

  • L’annonce automatique du score final conserve sa priorité ; les répétitions du score à la demande restent interruptibles. Aucun score n’est exposé pendant la partie.
  • La parole et le braille utilisent toujours Prism. Le mode automatique privilégie toujours un lecteur d’écran en cours d’exécution, puis OneCore, puis SAPI. Les profils de voix restent distincts.
  • Les valeurs par défaut des menus, les clés de préférences enregistrées, les noms INI modifiables, les affectations, les règles de fermeture de l’accueil et les textes traduits destinés aux joueurs restent compatibles.
  • L’expérience Trim Silence masquée reste dans le code source, comme demandé auparavant. Elle demeure inaccessible aux utilisateurs. Elle n’a pas été considérée comme du code mort accidentel.
  • Les historiques des builds, les imports source conservés et les anciens outils de création restent comme traces de provenance. Une migration obsolète est soumise à une activation explicite plutôt que d’effacer silencieusement cet historique.
  • La parole mise en file, les vérifications de repli natif et les vérifications répétées d’admission autour des verrous restent en place lorsqu’elles protègent l’ordre ou les changements d’état concurrents. Une implémentation plus courte ne suffit pas à justifier la suppression d’une protection.
  • Les assemblies générées du jeu et les fichiers compilés du mod et de l’installateur restent hors de Git. Les références de compilation continuent d’utiliser l’installation du joueur avec la copie désactivée.
  • Aucune modification spéculative n’a été apportée au minutage natif du jeu, à la planification de la calibration, aux règles de score ou aux formulations traduites lorsque la revue statique n’a pas établi de défaut.

Compilation et limites pratiques

Le mod intégré .NET 6 x64 0.9.8 a été compilé en Release et Debug sans avertissement ni erreur. La publication de l’installateur autonome Windows x64 0.1.5 s’est terminée sans diagnostic après la dernière modification source. Ces compilations réussies ne prouvent pas la correction à l’exécution. Aucun test, session de jeu, installation, désinstallation ni mesure de performances n’a été exécuté pour ce build.

Les déclarations P/Invoke de Prism ont été comparées à l’en-tête C public fixé à v0.18.3. Cela peut détecter des incohérences de déclaration ; cela ne prouve pas le comportement de chaque pilote natif, lecteur d’écran, voix ou afficheur braille.

Les plantages de DLL natives et les appels bloqués aux pilotes ne peuvent pas toujours être récupérés dans le code managé. L’arrêt utilise donc une attente bornée et évite de libérer un contexte depuis un autre thread. Un lot de parole échoué est consigné puis abandonné ; les demandes suivantes peuvent continuer, mais le texte échoué n’est pas répété automatiquement.

Certains rappels de calibration observent encore l’état natif depuis des rappels FMOD. Les protections existantes contiennent les exceptions managées, mais la revue statique ne peut pas prouver tous les comportements temporels entre threads. Modifier cette planification sans essais humains pourrait affecter la calibration ; cela reste donc un point précis à examiner ultérieurement.

Le guide reste un lecteur léger des documents HTML fournis, plutôt qu’un navigateur généraliste. Ses nouvelles limites refusent volontairement les documents anormalement grands ou profondément imbriqués et utilisent un repli sûr. Le nettoyage de l’installateur peut rester incomplet si Windows refuse l’accès à un profil ; le lanceur et le point de reprise conservés permettent une tentative ultérieure.

Les modifications de performances suppriment du travail répété et des allocations identifiables. Aucune amélioration mesurée de fréquence d’images, de latence ou de mémoire n’est revendiquée. Avant publication, les vérifications humaines devraient couvrir les réaffectations natives et personnalisées, le maintien et le relâchement des entrées d’ouverture, l’accueil du premier lancement, tous les tableaux du guide, l’ordre score puis menu, les changements OneCore/SAPI et le fonctionnement en arrière-plan. L’annulation de l’installateur, la récupération interrompue, la conservation des chargeurs partagés et les nouvelles tentatives de nettoyage des préférences nécessitent aussi des vérifications sur une installation d’essai jetable.

L’absence de problème constaté par cette revue ne garantit pas que le projet soit sans défaut. Ce build est un candidat de préparation à la publication, pas la version publique 1.0.

La configuration modifiable utilise des empreintes et un remplacement atomique, mais la dernière comparaison et le renommage ne constituent pas une opération de comparaison et échange du système d’exploitation : un éditeur non coopératif peut écrire pendant ce court intervalle. Un arrêt forcé peut laisser un fichier temporaire unique ; la désinstallation supprime uniquement les noms détenus et validés. La persistance des préférences natives du jeu et de Steam peut écrire partiellement avant de lever une exception et ne possède pas d’API de transaction commune.

Les anciennes installations manuelles n’ont pas de registre de propriété durable. Leur suppression ne peut concerner que les fichiers connus du mod et les dépendances identifiées avec sûreté ; les avertissements de nettoyage permettent une nouvelle tentative dans l’installateur ouvert. La conservation de l’entrée Windows et du point de reprise concerne les copies gérées par l’installateur. Des sauvegardes manquantes, un accès refusé aux profils, des lecteurs indisponibles ou une détection prudente des chargeurs partagés peuvent nécessiter une nouvelle tentative ; ces cas sont signalés plutôt que de supprimer silencieusement des fichiers incertains.

Le nettoyage des ressources d’entrée est destiné à l’arrêt de l’application sur le thread Unity. Une future désactivation à chaud alors que le jeu continue devra retirer les lignes clonées et les références d’invite avant de détruire les ressources d’entrée du mod qu’elles référencent. Les appels aux pilotes natifs, l’ordre des captures avec plusieurs manettes et les rappels de calibration nécessitent encore des vérifications humaines à l’exécution.

Les six scripts Python de création ont passé la compilation syntaxique avec py_compile. L’analyseur AST de PowerShell n’a signalé aucune erreur de syntaxe pour uninstall.ps1 et prepare_prism.ps1. Ces vérifications n’ont pas exécuté les fonctions des scripts, téléchargé de dépendances ni exercé l’installation ou la suppression.

Le SDK portable est préparé avant la transaction sur les fichiers. Une annulation interceptée supprime son dossier de préparation, mais une coupure de courant pendant l’extraction peut laisser ce dossier unique. Une désinstallation ordinaire conserve volontairement le SDK. Si un nouvel installateur détient le mutex de nettoyage au réveil d’un ancien programme auxiliaire de nettoyage, celui-ci conserve le dossier d’état ; les enregistrements de désinstallation terminée permettent de réessayer le nettoyage plus tard.
