# Bop It Access の Git 作業手順

Git は、このプロジェクトのソースコードとドキュメントの履歴を保存します。**コミット**とは、確認したり戻ったりできる、名前の付いたスナップショットです。GitHub にコミットを公開すると、他の人が変更を読み、自分でプロジェクトをビルドできます。コミットを作成しても、一般公開リリースが自動的に作成されるわけではありません。

## これまでの履歴について

`0.1.0` から `0.6.12` までの最初の 37 ソースビルドは、残っていたソースアーカイブと元の変更メモを使い、それぞれ別のコミットとして取り込まれました。Git の日時は、元のビルド日時ではなく取り込み日時を示しています。その後の作業は、ソースのコミットに直接記録されています。現在は Git と GitHub がプロジェクトの変更履歴であり、別のビルド履歴文書は維持していません。

コミットの作成者には、Christopher Shaw の GitHub no-reply アドレスを使用します。AI が協力したコミットには、実際に貢献したモデル名を記載した `Co-authored-by` 行を付けます。セッション記録では、最初の履歴ビルドが GPT-6 Luna、その後の 36 ビルドが GPT-6 Sol です。今後のコミットには、その作業に貢献したモデルの現在の名前を使ってください。

コンパイル済み DLL、インストーラー、リリース ZIP、生成されたゲームのアセンブリ、個人のログ、一時的なビルド出力は、Git のソース履歴に含めません。ローカルのバージョンタグは自動公開されません。GitHub リリースの作成は、別途、意図して行う作業です。

## 便利なコマンド

リポジトリのフォルダーで PowerShell を開き、次を実行します。

```powershell
git status                 # See changed, added and untracked files
git diff                   # Inspect changes that are not staged
git log --oneline           # Browse commits
git show --stat HEAD~1      # Inspect the previous commit's changed files
```

順に、変更・追加・未追跡のファイルの表示、ステージしていない変更の確認、コミットの一覧、前のコミットで変更されたファイルの確認を行います。これらのコマンドはリポジトリを確認するだけで、インストール済みの MOD やゲームを変更しません。

## 今後の変更ごとの手順

1. 意図したソースとドキュメントの変更を行います。新しいビルドでは、バージョンを更新します。
2. 影響を受けるすべての翻訳済みガイドを更新します。コンパイル済みの配布物にはプレイヤー向けドキュメントとライセンスの通知を含めます。開発者向け README とこの作業手順は、プレイヤー向けリリースには含めません。
3. 新しいバイナリが必要な変更ではコンパイルし、ローカルのファイルを準備します。ゲームプレイのテストは、依頼された際に人間のプレイヤーが行います。コンパイルしただけで、実行時の動作まで確認済みと表現しないでください。
4. `git status` と `git diff` を実行します。対象ファイルをステージした後、`git diff --cached` を確認します。生成されたバイナリ、個人のログ、ゲームの参照ファイルはステージする変更に含めません。
5. 内容が分かるコミットを作成します。件名にはバージョン番号を含めません。本文には、何を変更し、その理由は何か、関連する確認事項や制限があればそれも記載します。AI が貢献した場合は、実際のモデル名を共同作成者の行に含めます。

   ```text
   Co-authored-by: MODEL NAME <noreply@openai.com>
   ```

   `MODEL NAME` を、その作業を書いたモデルの名前に置き換えてください。作成者は Christopher Shaw のままとし、アドレスは `336230252+Chris-E-Shaw@users.noreply.github.com` を使います。
6. 変更を公開する準備ができたら、`git push origin main` を実行します。これによりブランチのコミットが公開されますが、ローカルのタグは送られず、リリースも作成されません。

ソースとドキュメントが一つのまとまった変更を表す場合は、同じコミットに含められます。独立した変更を記録するときは、コミットを分けることも有用です。Git は作業を自動でアップロードしません。他の人が読める状態になった時点で、意図して push してください。
