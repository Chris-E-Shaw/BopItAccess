Bop It Access：リリース準備コードレビュー

Mod 0.9.8 およびインストーラープレビュー 0.1.5。予定されている 1.0 リリースに向け、Christopher Shaw のために 2026 年 10 月 7 日に作成。

追加の修正 — 2026年10月7日

このレビュー後のプレイヤーによる確認で、v0.9.8 の不具合が見つかった。重複チェックが Bop の上矢印キーへの割り当てや、新たに空いたスペースキーへの Twist の割り当てなど、有効なネイティブの再割り当てを拒否していた。修正内容は履歴の v0.9.9 の項目に記録されている。この報告書は元の v0.9.8 レビューの記録を保持しており、コンパイル結果は実行時の動作確認を意味するものではない。

対象範囲と方法

静的レビューでは、Mod とインストーラーのすべての C# ソースファイル、アンインストールスクリプト、プロジェクトのビルド定義、設定テンプレート、文書・カタログ作成スクリプトを対象としました。所有権、終了処理、並行処理、ナビゲーションと再割り当ての遷移、破損ファイル、ネイティブのフォールバック経路、フレームごとの処理、繰り返される状態確認、未使用コードを検討しました。並行して作業したレビュアーは音声・オーディオ・画面、入力・設定・ツール、インストール・復旧を担当し、統括レビュアーはルーティング、ヒント、ガイドのナビゲーション、Mod Settings、ウェルカム処理を担当しました。統合後の変更には 2 回目のソースレビューを行いました。

これはコードレビューとコンパイルの記録です。今回の変更について、ゲームの実行、インストーラーの操作、アンインストールの操作、自動テストスイート、性能ベンチマークは実施していません。過去の人によるテストは有用ですが、このリファクタリングの実行時の動作を証明するものではありません。

意図的に維持した動作とコード

  • 自動の最終スコア読み上げは優先順位を維持し、要求に応じたスコアの再読み上げは割り込み可能なままです。プレイ中にスコアは公開されません。
  • 音声と点字は引き続き Prism を使用します。自動モードは実行中のスクリーンリーダー、OneCore、SAPI の順に優先します。音声プロファイルは別々に維持します。
  • メニューの既定値、保存設定キー、編集可能な INI 名、割り当て、ウェルカムを閉じる規則、翻訳されたプレイヤー向け文字列は互換性を維持します。
  • 以前の要望に従い、非表示の Trim Silence 実験はソースに残します。引き続きエンドユーザーは利用できません。誤って残った未使用コードとは扱いませんでした。
  • 過去のビルド記録、保存されたソースインポート、旧作成ツールは由来の記録として残します。古い移行はその記録を黙って削除せず、有効化を制限します。
  • 音声キュー、ネイティブのフォールバック確認、ロックの前後にある繰り返しの受付確認は、順序や並行状態変更を保護する場合に維持します。実装が短くなるだけでは、保護を削除する十分な理由になりません。
  • 生成されたゲームアセンブリとコンパイル済みの Mod・インストーラーファイルは Git の外に置きます。ビルド参照は引き続きプレイヤー自身のインストールを使用し、コピーを無効にします。
  • 静的レビューで欠陥を確認できなかったネイティブのゲームタイミング、キャリブレーションのスケジュール、スコアルール、翻訳文言には、推測による変更を行いませんでした。

コンパイルと実用上の制約

統合後の .NET 6 x64 Mod 0.9.8 は、Release と Debug の両方で警告・エラー 0 件でコンパイルされました。Windows x64 の自己完結型インストーラー 0.1.5 は、最終ソース変更後、診断 0 件で publish を完了しました。このコンパイル成功は実行時の正しさを証明しません。このビルドについて、テスト、ゲームの実行、インストール、アンインストール、ベンチマークは実施していません。

Prism の P/Invoke 宣言を、固定した v0.18.3 の公開 C ヘッダーと比較しました。宣言の不一致は検出できますが、すべてのネイティブドライバー、スクリーンリーダー、音声、点字ディスプレイの動作を証明することはできません。

ネイティブ DLL のクラッシュや、ブロックしたドライバー呼び出しは、マネージドコードで常に復旧できるとは限りません。そのため、終了時の待機に上限を設け、別スレッドからコンテキストを解放しないようにしています。失敗した音声バッチは記録して破棄します。後続の要求は続行できますが、失敗したテキストは自動では再読み上げしません。

一部のキャリブレーションコールバックは、引き続き FMOD コールバックからネイティブ状態を参照します。既存の保護でマネージド例外は封じ込めますが、静的レビューではスレッド間のすべてのタイミング動作を証明できません。人によるプレイテストなしにこのスケジュールを変更すると、キャリブレーションに影響する可能性があるため、具体的な追加確認対象として残します。

ガイドは引き続き、提供された HTML 文書を読む軽量リーダーです。汎用ブラウザーではありません。新しい上限は、異常に大きい文書や深く入れ子になった文書を意図的に拒否し、安全にフォールバックします。Windows がプロファイルへのアクセスを拒否すると、インストーラーのクリーンアップが未完了になる場合があります。保持されるランチャーとチェックポイントにより、後で再試行できます。

性能変更では、特定できた繰り返し処理と割り当てを削除します。フレームレート、遅延、メモリの改善を測定したとは主張しません。リリース前の人による確認では、ネイティブとカスタムの再割り当て、画面を開く入力の押下・解放、初回ウェルカム、すべてのガイド表、メニューより前のスコア読み上げ順序、OneCore/SAPI 切り替え、バックグラウンド動作を確認する必要があります。インストーラーの中止、中断後の復旧、共有ローダーの維持、設定値クリーンアップの再試行も、使い捨てのテスト用インストールで確認する必要があります。

このレビューで問題が見つからなかったとしても、プロジェクトに欠陥がない保証にはなりません。このビルドはリリース準備候補であり、1.0 の公開リリースではありません。

編集可能な設定はフィンガープリントとアトミックな置換を使いますが、最後の比較と名前変更は OS の compare-and-swap ではありません。協調しないエディターは、その短い間隔に書き込めます。強制終了により固有の一時ファイルが残る場合があり、アンインストールでは所有が検証された名前のみを削除します。ネイティブゲーム・Steam の設定保存は、例外を送出する前に一部を書き込む可能性があり、共通のトランザクション API がありません。

旧手動インストールには永続的な所有権台帳がありません。削除対象にできるのは既知の Mod ファイルと安全に特定できる依存関係のみです。クリーンアップ警告は、開いているインストーラーで再試行できます。保持される Windows 登録・チェックポイントの経路は、インストーラー管理のコピーに適用されます。バックアップの欠如、プロファイルのアクセス拒否、利用不能なドライブ、慎重な共有ローダー検出により、後の再試行が必要な場合があります。不確かなファイルを黙って削除せず、これらを報告します。

入力アセットのクリーンアップは、Unity スレッド上でアプリケーションを終了するためのものです。将来、ゲームを継続するホットアンロード経路を追加する場合、参照先の Mod 入力アセットを破棄する前に、複製行とプロンプトの参照を削除する必要があります。ネイティブドライバーの呼び出し、複数コントローラーの入力取得順序、キャリブレーションコールバックには、引き続き人による実行時確認が必要です。

6 つすべての Python 作成スクリプトが py_compile による構文コンパイルに合格しました。PowerShell の AST パーサーは uninstall.ps1 と prepare_prism.ps1 について構文エラー 0 件を報告しました。これらの確認では、スクリプトの機能を実行せず、依存関係をダウンロードせず、インストール・削除を試していません。

ポータブル SDK はファイルのトランザクション前に準備されます。処理できたキャンセルでは準備用ディレクトリを削除しますが、展開中に電源が失われると、その一意のディレクトリが残る場合があります。通常のアンインストールでは意図的に SDK を残します。古いクリーンアップ補助プロセスが動作を再開した時点で新しいインストーラーがクリーンアップ用ミューテックスを所有している場合、補助プロセスは状態フォルダーを保持します。アンインストール完了の記録を使って、後でクリーンアップを再試行できます。
