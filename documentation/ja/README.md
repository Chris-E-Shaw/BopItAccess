# Bop It Access

Bop It Access は、**Bop It!** の Windows Steam バージョン用の非公式アクセシビリティ MOD です。 MelonLoader を使用し、 [Prism](https://github.com/ethindp/prism) メニューやゲーム画面に音声と点字のフィードバックを追加します。現在の機能には、初回起動時のウェルカム画面、ゲーム内ユーザーガイド、音声タイトルと一時停止画面、設定とコントロール、曲の選択、最終スコアとリーダーボード、実績、クレジット、ボタンのヒント、ラウンド前の現在のコントロール割り当てを含むオンデマンドのチュートリアル テキスト、および 4 つのステージの説明が含まれます。バージョン 0.9.0 は、音声および点字出力に Prism を使用します。この MOD はゲームで選択された言語に従い、ゲームが提供するすべての言語のガイドが含まれています。

## プロジェクトのステータス

このプロジェクトは開発初期段階にあります。このリポジトリには、ソース コードと技術ドキュメントが含まれています。 **ここにはコンパイルされたビルドや GitHub リリースはまだありません。** このリポジトリの MOD を使用するには、ソースからビルドし、以下で説明する Prism ランタイムを提供します。

コミット履歴には、37 個の以前のビルドの再構築されたソース スナップショットが含まれています。コミットは、アーカイブが Git にインポートされたときに作成されました。それらの日付は元のビルド日ではありません。の [技術的なビルド履歴](BopItAccess-build-history.html) では、各スナップショットの背後にある作業について説明します。

## 要件

- Windows x64、および Steam の場合は Bop It! の独自のインストール。
- MelonLoader はゲームのディレクトリにインストールされます。開発では、x64 Unity **2022.3.50f1** ゲーム ビルドの MelonLoader **0.7.3 オープンベータ** を使用しました。他の組み合わせは未確認です。
- **.NET 6 ターゲティング パック**を備えた .NET SDK (MOD はターゲットをターゲットにしているため) `net6.0`.
- インストールするには、公式 Windows x64 Prism v0.18.3 `prism.dll`。このサードパーティのバイナリはこのリポジトリにありません。

この MOD は、ゲーム ディレクトリの下にある MelonLoader によって生成またはインストールされた DLL を参照します。ゲーム アセンブリは含まれず、再配布もされません。

<a id="build-from-source"></a>
## ソースからビルドする

1. MelonLoader をインストールし、Bop It! を一度起動してからゲームを終了します。 MelonLoader を作成する必要があります `MelonLoader\Il2CppAssemblies` ゲームディレクトリの下にあります。
2. このリポジトリを複製またはダウンロードします。リポジトリのルート ディレクトリで PowerShell を開きます。
3. セット `$gameDir` **あなたの** Bop It! インストール ディレクトリに移動し、以下をビルドします。

   ```powershell
   $gameDir = 'C:\Program Files (x86)\Steam\steamapps\common\Bop It!'
   dotnet build .\src\BopItAccess.csproj -c Release "-p:BopItGameDir=$gameDir"
   ```

   パスの例は、Steam の通常の Windows の場所です。 Steam ライブラリが別の場所にある場合は変更してください。プロジェクトは、コンパイル前に必要な MelonLoader および生成されたゲーム DLL をチェックし、欠落しているパスを報告します。

4. ビルドされた MOD DLL は次の場所にあります。 `src\bin\Release\net6.0\BopItAccess.dll`.

SDK が .NET 6 ターゲット パックの欠落を報告する場合は、そのパックを含む SDK をインストールします。プロジェクトの `NuGet.Config` オンライン パッケージ フィードを構成しません。

<a id="install-your-build"></a>
## ビルドをインストールする

1. ゲームを終了します。ビルドした `BopItAccess.dll` を `<game directory>\Mods\` にコピーします。MelonLoader が `Mods` フォルダーを作成していない場合は、自分で作成してください。
2. [Prism のリリースページ](https://github.com/ethindp/prism/releases)から、Windows x64 用の公式 Prism v0.18.3 `prism.dll` を入手します。同じバージョンをソースからビルドすることもできます。`prism.dll` はゲームの実行ファイルと同じフォルダーに置き、`Mods` フォルダーには入れないでください。
3. ビルドされた `src\bin\Release\net6.0\documentation\` フォルダーを丸ごとゲームのフォルダーにコピーします。フォルダーの直下には英語のガイドがあり、`fr`、`it`、`de`、`es`、`es-MX`、`ja`、`ko`、`zh`、`pt-BR` の各サブフォルダーに翻訳版があります。関連ドキュメントも一緒に残してください。ゲーム内ガイドは開くたびに現在のゲーム言語に対応する HTML を読み込むため、DLL を再ビルドしなくてもガイドを更新できます。
4. スクリーンリーダーを使う場合はゲームより先に起動してください。対応するスクリーンリーダーが動作していない場合、Prism は OneCore を優先し、利用できなければ SAPI を使います。

Bop It Access のビルドコマンドがコンパイルするのは、この MOD だけです。Prism はビルドもダウンロードもされません。音声が出ない場合は、`<game directory>\Mods\BopItAccess.log` を確認してください。ログには Prism の初期化と音声の送信が記録されますが、送信が成功していても、実際に音が聞こえたとは限りません。

最初の実行では、ゲームのメイン メニューの準備ができた後、ようこそ画面が表示されます。その選択により、Mod 設定を開くか、ゲーム内のユーザー ガイドを読むか、ゲームを続行することができます。 Mod 設定では、**ユーザー ガイドを開く** と、次回起動時にようこそ画面を表示する確認済みの **ようこそ画面をリセット** アクションも提供します。ガイドでは、上/下を使用してトピックを選択するか行を読み、確認を使用してトピックを開きます。テーブル内で、Left は 1 列左に移動し、Right は 1 列右に移動し、Up/Down は行を変更しながら現在の列を保持します。列見出しはデータ行として表示されるのではなく、セルにラベルを付けます。テーブルは入場時にアナウンスされ、退場時にテーブルの終了がアナウンスされます。戻るはトピックまたはガイドを残します。

ゲームの **[設定] > [言語]** 行で言語を選択します。 Mod スピーチはその選択に従います。ゲーム内ガイドは、一致する翻訳された HTML ドキュメントを使用します。選択したコピーが見つからない場合、または読めない場合は、代替として英語が使用されます。バンドルされている英語以外のテキストは、機械翻訳された最初のパスです。流暢な話者による修正は大歓迎です。

ゲーム操作の名前にはゲームの翻訳が使われます。Shapes、Space、City、Office は固定されたステージ名として英語のままです。 OneCore または SAPI を使う場合、既定の音声がゲームの言語を正しく読まなければ、Mod 設定で適切なインストール済み音声を選んでください。 「音声」「音量」「読み上げ速度」「音程」は、Auto モードでも実際に使用中の OneCore または SAPI を調整します。対応する項目だけが表示され、ほかの出力方式では非表示になります。設定はエンジンごとに別々に保存されます。

**読み上げを整える**: 英字がすべて大文字のテキストを、音声と点字で自然に読めるように整えます。ゲーム内ガイドでは、行末に句読点がない場合、行番号の前に三点リーダーを加えて間を置きます。画面の文字は変わりません。オフにすると元のテキストのまま出力します。

## AIの透明性

Christopher Shaw はこのプロジェクトを監督し、ゲーム内でのアクセシビリティを評価しています。 OpenAI Codex モデルは、研究、コード、ドキュメント化に役立ちました。公開されたコミット メッセージには、 `Co-authored-by` 各変更に貢献したモデルを特定するトレーラー。過去のクレジットは、このプロジェクトのセッション記録と照合されました。以前のビルド履歴は、当時のコミットとして記録されるのではなく、保存されたソース アーカイブから再構築されました。 AI 支援による投稿には間違いが含まれる可能性があるため、使用前にレビューする必要があります。
