# Bop It Access

現在のソースビルドはMod 0.9.12（59件のModビルド）、インストーラー0.2.5です。最初の公開リリースは今後の予定です。

Bop It Access は、**Bop It!** の Windows Steam バージョン用の非公式アクセシビリティ MOD です。 MelonLoader を使用し、 [Prism](https://github.com/ethindp/prism) メニューやゲーム画面に音声と点字のフィードバックを追加します。現在の機能には、初回起動時のウェルカム画面、ゲーム内ユーザーガイド、音声タイトルと一時停止画面、設定とコントロール、曲の選択、最終スコアとリーダーボード、実績、クレジット、ボタンのヒント、ラウンド前の現在のコントロール割り当てを含むオンデマンドのチュートリアル テキスト、および 4 つのステージの説明が含まれます。バージョン 0.9.0 は、音声および点字出力に Prism を使用します。この MOD はゲームで選択された言語に従い、ゲームが提供するすべての言語のガイドが含まれています。

## 設定ファイルを編集する

知らない言語、大きすぎるゲーム音、または問題のある音声のためにメニューを操作しにくい場合は、ゲームの外から設定を変更できます。起動後、Modは現在の設定を使ってBop It!のゲームフォルダー内にUserData/BopItAccess.iniを自動作成します。メモ帳などのエディターで開けるテキストファイルです。

ファイルには、ゲームの言語、音楽・効果音・ナレーションの音量、振動、全画面表示、解像度、音声遅延、Modの読み上げ・点字・ヒントなどの設定、OneCoreとSAPIの個別の音声設定、プレイヤー向けのゲームとModの操作割り当てが含まれます。利用できる解像度とインストール済みの音声はコメントに記載されます。

編集する前にゲームを終了してください。該当するセクションで既存の項目の値を変更し、ファイルを保存してからゲームを再起動します。変更は起動時に読み込まれ、プレイ中に即座には反映されません。ゲーム内のメニューで変更した設定は、自動的にファイルにも保存されます。

セクション名と設定名は、どの言語でも共通の英語のままです。切り替え項目にはOnとOffをお勧めします。True/False、Yes/No、1/0も使用できます。コメントに選択肢と範囲が説明されています。項目がない場合や値が無効な場合は、その項目の保存済み設定が維持され、他の有効な変更は反映されます。重複した操作割り当ては拒否されます。

コメントと未知の項目は保持されます。ゲームの実行中に他のプログラムがファイルを変更すると、その編集を保護するため、Modはそのセッション中のファイルへの自動保存を停止します。変更を反映するには、ゲームを終了して再起動してください。編集前にバックアップを残しておくこともできます。

音声に問題がある場合は、OneCoreまたはSAPIセクションでVoice=System defaultに設定します。OneCoreの音声は名前 | 言語の形式を使います。SAPIはインストール済み音声の表示名または完全なレジストリIDを使用できます。利用できる選択肢はファイルに記載されます。OutputMode=Autoは、実行中の対応スクリーンリーダー、OneCore、SAPIの順に出力を試します。

下の例は、言語を英語に戻し、ゲーム音を小さくし、システム既定の音声による自動読み上げを有効にします。ファイル内にすでにある該当項目を変更してください。これは参考用の抜粋で、末尾に追加する新しいブロックではありません。他の設定はそのまま残してください。

```ini
[Game]
Language=en
MusicVolume=30
SfxVolume=30
VoiceOverVolume=30

[Mod]
SpeechOutput=On
OutputMode=Auto

[OneCore]
Voice=System default

[SAPI]
Voice=System default
```

Uninstall を確認した後、Uninstall for me または Uninstall for everyone を選びます。どちらもこのゲームフォルダーの共有 Mod ファイルを削除するため、そのゲームを使う誰にとっても Mod は利用できなくなります。選択によって変わるのは Windows に保存された Mod 設定の削除対象です。操作を要求した自分のアカウントだけか、サインアウト中のアカウントを含むすべてのローカル Windows プロファイルかを選べます。元のゲームの設定は保持します。.NET SDK もインストール済みのまま残ります。

インストーラー自身が導入した MelonLoader を削除し、他の Mod が必要としていない場合は、既知の Loader.cfg と MelonPreferences.cfg、空の Plugins、UserLibs、UserData フォルダーも削除します。Bop It Access の設定、既知のログ、ガイド、インストーラーのファイルを削除します。他の Mod、以前からある共有ローダーファイル、認識できないファイルは保護します。そのため、未知のファイルがあるとフォルダーが残る場合があります。無関係のデータを消す代わりに、診断情報にそのことを記録します。

Windows の「インストールされているアプリ」からも同じ確認、設定の削除対象の選択、クリーンアップを使います。インストーラーはゲームフォルダーに BopItAccess-uninstall.ps1 を配置します。これはインストール済みのアンインストーラーへのショートカットです。今後のソースビルドの出力にも含まれます。スクリプトを手動でコピーするだけではアンインストーラー自体はインストールされません。所有権記録のない古い手動インストールでは、識別できる Mod ファイルだけを削除し、由来を確認できない共有ファイルは残します。

クリーンアップを安全に完了できない場合は理由を知らせ、再試行に必要な情報を保持します。管理対象のインストールでは削除が成功するまで Windows のアンインストール項目と再開地点を残します。古い手動コピーには永続的な所有権記録がありません。その警告は開いているインストーラーで再試行してください。Bop It! の実行中には Mod のインストール、更新、削除を行わないでください。

## プロジェクトのステータス

このプロジェクトは基本的に完了しており、主要なコンテンツや機能の予定はありません。プレイヤーのフィードバックを改善に導きながら、必要に応じて維持されます。 GitHub リポジトリには、ソース コードと技術ドキュメントが含まれています。 **GitHub のリリースはまだありません。** ソースには Windows インストーラー プロジェクトも含まれています。リリースが公開されるまで、[*インストール**] ボタンには利用可能なリリースがないことが表示されます。 **アルファ版のインストール** は、ソースから最新のメインブランチ コミットをビルドします。

コミット履歴には、37 個の以前のビルドの再構築されたソース スナップショットが含まれています。コミットは、アーカイブが Git にインポートされたときに作成されました。それらの日付は元のビルド日ではありません。の [技術的なビルド履歴](BopItAccess-build-history.html) では、各スナップショットの背後にある作業について説明します。

## 要件

- Windows x64、および Steam の場合は Bop It! の独自のインストール。
- MelonLoader はゲームのディレクトリにインストールされます。開発では、x64 Unity **2022.3.50f1** ゲーム ビルドの MelonLoader **0.7.3 オープンベータ** を使用しました。他の組み合わせは未確認です。
- **.NET 6 ターゲティング パック**を備えた .NET SDK (MOD はターゲットをターゲットにしているため) `net6.0`.
- インストールするには、公式 Windows x64 Prism v0.18.3 `prism.dll`。このサードパーティのバイナリはこのリポジトリにありません。

この MOD は、ゲーム ディレクトリの下にある MelonLoader によって生成またはインストールされた DLL を参照します。ゲーム アセンブリは含まれず、再配布もされません。

<a id="build-from-source"></a>
## ソースからビルドする

1. MelonLoader をインストールし、Bop It! を一度起動してからゲームを終了します。 MelonLoader を作成する必要があります `MelonLoader\Il2CppAssemblies` ゲームディレクトリの下にあります。
2. このリポジトリを複製またはダウンロードします。リポジトリのルート ディレクトリで PowerShell を開きます。
3. セット `$gameDir` **あなたの** Bop It! インストール ディレクトリに移動し、以下をビルドします。

   ```powershell
   $gameDir = 'C:\Program Files (x86)\Steam\steamapps\common\Bop It!'
   dotnet build .\src\BopItAccess.csproj -c Release "-p:BopItGameDir=$gameDir"
   ```

   パスの例は、Steam の通常の Windows の場所です。 Steam ライブラリが別の場所にある場合は変更してください。プロジェクトは、コンパイル前に必要な MelonLoader および生成されたゲーム DLL をチェックし、欠落しているパスを報告します。

4. ビルドされた MOD DLL は次の場所にあります。 `src\bin\Release\net6.0\BopItAccess.dll`.

SDK が .NET 6 ターゲット パックの欠落を報告する場合は、そのパックを含む SDK をインストールします。プロジェクトの `NuGet.Config` オンライン パッケージ フィードを構成しません。

<a id="install-your-build"></a>
## ビルドをインストールする

1. ゲームを終了します。ビルドした `BopItAccess.dll` を `<game directory>\Mods\` にコピーします。MelonLoader が `Mods` フォルダーを作成していない場合は、自分で作成してください。
2. [Prism のリリースページ](https://github.com/ethindp/prism/releases)から、Windows x64 用の公式 Prism v0.18.3 `prism.dll` を入手します。同じバージョンをソースからビルドすることもできます。`prism.dll` はゲームの実行ファイルと同じフォルダーに置き、`Mods` フォルダーには入れないでください。
3. ビルドされた `src\bin\Release\net6.0\documentation\` フォルダーを丸ごとゲームのフォルダーにコピーします。フォルダーの直下には英語のガイドがあり、`fr`、`it`、`de`、`es`、`es-MX`、`ja`、`ko`、`zh`、`pt-BR` の各サブフォルダーに翻訳版があります。関連ドキュメントも一緒に残してください。ゲーム内ガイドは開くたびに現在のゲーム言語に対応する HTML を読み込むため、DLL を再ビルドしなくてもガイドを更新できます。
4. スクリーンリーダーを使う場合はゲームより先に起動してください。対応するスクリーンリーダーが動作していない場合、Prism は OneCore を優先し、利用できなければ SAPI を使います。

Bop It Access のビルドコマンドがコンパイルするのは、この MOD だけです。Prism はビルドもダウンロードもされません。音声が出ない場合は、`<game directory>\Mods\BopItAccess.log` を確認してください。ログには Prism の初期化と音声の送信が記録されますが、送信が成功していても、実際に音が聞こえたとは限りません。

最初の実行では、ゲームのメイン メニューの準備ができた後、ようこそ画面が表示されます。その選択により、Mod 設定を開くか、ゲーム内のユーザー ガイドを読むか、ゲームを続行することができます。 Mod 設定では、**ユーザー ガイドを開く** と、次回起動時にようこそ画面を表示する確認済みの **ようこそ画面をリセット** アクションも提供します。ガイドでは、上/下を使用してトピックを選択するか行を読み、確認を使用してトピックを開きます。テーブル内で、Left は 1 列左に移動し、Right は 1 列右に移動し、Up/Down は行を変更しながら現在の列を保持します。列見出しはデータ行として表示されるのではなく、セルにラベルを付けます。テーブルは入場時にアナウンスされ、退場時にテーブルの終了がアナウンスされます。戻るはトピックまたはガイドを残します。

ゲームの **[設定] > [言語]** 行で言語を選択します。 Mod スピーチはその選択に従います。ゲーム内ガイドは、一致する翻訳された HTML ドキュメントを使用します。選択したコピーが見つからない場合、または読めない場合は、代替として英語が使用されます。バンドルされている英語以外のテキストは、機械翻訳された最初のパスです。流暢な話者による修正は大歓迎です。

ゲーム操作の名前にはゲームの翻訳が使われます。Shapes、Space、City、Office は固定されたステージ名として英語のままです。 OneCore または SAPI を使う場合、既定の音声がゲームの言語を正しく読まなければ、Mod 設定で適切なインストール済み音声を選んでください。 「音声」「音量」「読み上げ速度」「音程」は、Auto モードでも実際に使用中の OneCore または SAPI を調整します。対応する項目だけが表示され、ほかの出力方式では非表示になります。設定はエンジンごとに別々に保存されます。

メニュー内の位置を読み上げる. この設定は保存され、初期状態ではオンです。選択中の項目がメニュー内の何番目かを読み上げます。 1対1のフィードバックは設定が保存され、初期状態ではオンです。開始時と切り替わった時に、現在の色を読み上げます。ライフを失った時は残りの数だけを読み上げます。ライフを獲得した時は「緑、ライフ3」のようにプレイヤーの色と新しい合計を読み上げるので、どちらが先に叩いたか分かります。1対1のフィードバックをオフにすると、これらの読み上げは行われません。ゲームの上限はこれまでどおり3ライフです。この機能は1対1のプレイ中だけ動作します。 最後の調整入力が登録されると、MODはすぐに「完了！」と読み上げます。叩くのをやめて、測定結果を待ってください。入力がなく調整に失敗した場合は「調整に失敗しました。」と読み上げます。

**読み上げを整える**: 英字がすべて大文字のテキストを、音声と点字で自然に読めるように整えます。ゲーム内ガイドでは、行末に句読点がない場合、行番号の前に三点リーダーを加えて間を置きます。画面の文字は変わりません。オフにすると元のテキストのまま出力します。

### MelonLoader 起動ウィンドウ

付属のLoader.cfgテンプレートは、MelonLoaderの独立したスタート画面とコンソールを非表示にします。インストーラーは、ユーザーがゲームを起動する前にこの2つの既定値を適用します。ゲームのタイトル画面やModのようこそ画面は省略されません。

ゲームを閉じて、ゲームフォルダー内の `UserData/Loader.cfg` を開きます。すでにファイルがある場合は、既存の `[loader]` セクションで `disable_start_screen` を `true` に、既存の `[console]` セクションで `hide_console` を `true` に設定します。他の項目は変更しないでください。ファイルがない場合は、ビルドに付属する `UserData/Loader.cfg` テンプレート、またはソースコードの `configuration/Loader.cfg` をコピーします。既存の Loader.cfg をテンプレート全体で上書きしないでください。

```ini
[loader]
disable_start_screen = true

[console]
hide_console = true
```

Mod は起動のたびにこれらの値をリセットしません。問題調査のために必要なら、どちらの値も手動で false に戻せます。共有の MelonLoader を残すアンインストールでは、インストーラーが変更した値がそのままの項目だけを復元し、他の編集は保持します。インストーラー自身が導入した不要な MelonLoader を削除する場合は、既知の Loader.cfg と MelonPreferences.cfg も削除します。

### インストーラーをコントローラーで操作する

Xbox 型のコントローラーと、Windows が XInput を通じて認識する他のコントローラーに対応します。インストーラーの操作は、ゲーム内で割り当て変更できる操作とは別です。D パッドまたは左スティックで項目間を移動します。テキスト欄にフォーカスがある場合は、方向入力でそのテキストを確認します。バンパーは常に前後のフォーカス可能な項目へ移動します。A は選択中のボタンやチェックボックスを操作します。入力を受け付けるのは、このインストーラーまたはそのダイアログが最前面にある間だけです。

B はダイアログで戻る、またはキャンセルします。インストーラーのメインウィンドウでは、インストール中なら中止の確認、それ以外なら Quit と同じ動作になります。Start はメインウィンドウで Quit、ダイアログでは戻る操作です。Y（前面上側のボタン）は、インストーラーのテキスト欄にフォーカスがあるときにすべてのテキストを選択します。メインウィンドウでテキスト欄以外にフォーカスがある場合はShow advancedを切り替えます。状態ログなどインストーラーのテキスト欄では、Dパッドや左スティックが矢印キーと同じように動作します。左／右は文字単位、上／下は行単位で移動します。LTを押すとCtrl相当になり、左／右は単語単位、上／下は段落単位で移動します。RTを押すとShift相当になって選択範囲を広げ、LTとRTを同時に押すと単語や段落を選択します。Xは選択中のテキストだけをコピーするので、先に必要な部分を選択してください。キーボードのCtrl+Cも引き続き選択範囲をコピーします。テキストが選択されていない場合、カーソル位置の文字、単語、行、段落の確認もアクセシビリティ通知で伝えます。コピー成功時にはアクセシビリティ通知で確認し、選択範囲がない場合やコピーに失敗した場合も通知します。読み上げられるかどうかは、スクリーンリーダーのWindows通知への対応に依存します。Windows 標準のフォルダー選択や保存ダイアログのコントローラー操作は、まだ人による確認が必要です。フォルダーやファイル名の入力にはキーボードも使えます。XInput 非対応の機器は今回の実装の対象外です。

独立したWelcome and controls欄にコントローラーのテキスト確認操作が記載されています。Alt+Wで戻り、Alt+Lで変化するStatus logへ移動します。どちらも読み取り専用で、選択と確認が可能です。Show advancedはチェック状態を通知し、すべて選択は成功または空欄を通知します。 キーボードのCtrl+Aですべてのテキストを選択し、Ctrl+Cで選択範囲をコピーします。

インストーラー0.2.5は、テキスト確認、すべて選択、Show advancedのチェック状態、Copy diagnostics、その他の確認を含め、送信するすべての読み上げ通知で前のインストーラー音声を置き換えるよう要求します。LB/RBは引き続き新しいフォーカス項目を通知します。状態通知の頻度は変わらず、ログの各項目が自動的に読まれるわけではありません。実際の中断はスクリーンリーダーのWindows通知対応に依存し、人による確認がまだ必要です。

### インストーラーの診断情報

Show advanced を有効にすると Save diagnostics（Alt+D）と Copy diagnostics（Alt+C）が表示されます。自動 UTF-8 ログは %ProgramData%\BopItAccess\diagnostics にローカル保存します。Save diagnostics は選んだ .log または .txt ファイルに現在の完全なセッションを保存し、インストーラーを閉じるまで記録を続けます。Copy diagnostics はその時点の内容をコピーし、アクセシビリティ通知で完了を伝えます。インストールやアンインストールを試す前に保存しておくと、自動ログの削除後も記録を残せます。ステータス欄が短い説明を使っていても、ファイル、ダウンロード、コンパイラー、エラーの技術的詳細は診断情報に残ります。アップロードは行いません。ログには Windows ユーザー名や完全なパスを含む場合があるので、共有前に確認してください。意図的に外部へ保存したコピーはアンインストール後も残ります。

MelonLoader 導入後の最初の手動起動では、必要な補助ファイルのダウンロードやゲームのアセンブリの準備を行う場合があります。約 1 分、一部の環境ではそれ以上待ってください。MelonLoader が Mod を読み込むまで Mod は話せません。ゲームを開いたまま Bop It Access の起動アナウンスを待ち、タイトル画面、歓迎画面、またはメインメニューのアナウンスが聞こえてからゲームを操作してください。

[MelonLoader](https://github.com/LavaGang/MelonLoader#how-to-use-the-installer) · [.NET 6 Windows x64 runtime](https://dotnet.microsoft.com/en-us/download/dotnet/6.0)

2. そのフォルダーへ公式x64 MelonLoaderを導入し、.NET 6 x64ランタイムを確認します。まだゲームを起動せず、先にModを配置します。
3. コンパイル済みBopItAccess-v1.0.zipを一時フォルダーへ展開します。Mods/BopItAccess.dllをゲームのModsへコピーします。フォルダーを作成または統合し、他のModは削除しません。prism.dllはBopIt!.exeの隣へコピーします。
4. 全言語とPrismの通知・ライセンスを含め、documentationとTHIRD-PARTY-LICENSESを丸ごとコピーします。パッケージのREADME.txtとBopItAccess-uninstall.ps1もコピーします。このスクリプトはインストーラー管理のアンインストーラーへのショートカットだけです。コピーしても動作するアンインストーラーやWindowsのアプリ登録は作成されません。
5. UserData/Loader.cfgがなければテンプレートをコピーします。存在する場合は対応する節に[loader] disable_start_screen=trueと[console] hide_console=trueだけを統合し、他の設定は残します。既存の設定をテンプレートで上書きしないでください。
6. 使用するスクリーンリーダーを起動し、Steamからゲームを開きます。ModをModsへ置いた状態で、MelonLoaderが初回に補助ファイルを取得しアセンブリを生成する場合があります。Modの起動通知とメニュー音声を待ってから操作します。

手動更新ではゲームを終了し、新しいパッケージのMod、Prism、文書、ライセンスを同じ場所へコピーします。BopItAccess.ini、他のMod、無関係なファイルは残し、Loader.cfgは上記のように統合します。手動Modを無効化・削除するにはMods/BopItAccess.dllだけを削除します。さらに整理する場合は、このModのためにコピーしたファイルとUserData/BopItAccess.iniまたはその.tmpだけを削除し、共有されるPrism/MelonLoaderは残します。保存されたWindows設定は残る場合があります。手動ZIPには所有権記録や登録済みアンインストーラーがありません。後でインストーラーを使用する場合、Uninstallは以前の手動Modを識別して設定を整理し、所有者不明のファイルを保護します。 ModログはMods/BopItAccess.logとMods/BopItAccess.log.previousです。整理する場合はこれらの既知のModログだけを削除します。

開発者向け：scripts/package-mod.ps1は既にビルドされた対応Modと既知の文書・設定・Prismファイルをパッケージ化します。ソースとDLLのバージョンを確認し、ゲーム・生成・旧形式ファイルを除外します。コンパイルはせず、アーカイブと準備物はローカルに留まります。
