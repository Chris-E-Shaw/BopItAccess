Bop It Access: release preparation code review

Mod 0.9.8 and installer preview 0.1.5. Prepared on 7 October 2026 for Christopher Shaw before the planned 1.0 release.

Follow-up correction — 7 October 2026

Player testing after this review found a regression in v0.9.8: the duplicate-binding guard rejected valid native remaps, including Bop on the Up arrow and Twist on newly freed Space. The v0.9.9 history entry records the correction. This report remains the original v0.9.8 review snapshot; its compilation results were not runtime verification.

Scope and method

Static review covered every C# source file in the mod and installer, the uninstall script, project build definitions, configuration template and authoring scripts. The review considered ownership, shutdown, concurrency, navigation and rebinding transitions, damaged files, native fallback paths, per-frame work, repeated state checks and unused code. Parallel reviewers handled speech/audio/screens, input/configuration/tools and installation/recovery; the coordinating reviewer handled routing, hints, guide navigation, Mod Settings and welcome handling. Integration changes received a second source review.

This is a code review and compilation record. No game session, installer operation, uninstall operation, automated test suite or performance benchmark was run for these changes. Earlier human testing remains valuable but does not establish the runtime behavior of this refactor.

Behavior and code deliberately preserved

  • Automatic final-score speech retains priority; on-demand score repeats remain interruptible. No score is exposed during gameplay.
  • Speech and braille still use Prism. Automatic mode still prefers a running screen reader, then OneCore, then SAPI. Voice profiles remain separate.
  • Menu defaults, saved preference keys, editable INI names, bindings, welcome-dismissal rules and translated player-facing strings remain compatible.
  • The hidden Trim Silence experiment stays in the source, as previously requested. It remains unavailable to end users. It was not treated as accidental dead code.
  • Historical build records, preserved source imports and legacy authoring tools remain as provenance. An obsolete migration is gated rather than silently deleting that record.
  • Queued speech, native fallback checks and repeated admission checks around locks remain where they protect ordering or concurrent state changes. A shorter implementation is not sufficient reason to remove a safeguard.
  • Generated game assemblies and compiled mod/installer files remain outside Git. Build references continue to use the player’s own installation with copying disabled.
  • No speculative changes were made to native gameplay timing, calibration scheduling, score rules or translation wording where static review did not establish a defect.

Compilation and practical limits

The integrated .NET 6 x64 mod 0.9.8 compiled in Release and Debug with zero warnings and errors. The Windows x64 self-contained installer 0.1.5 publish completed with zero diagnostics after the final source change. These successful compilations do not establish runtime correctness. No tests, game session, installation, uninstall or benchmark was run for this build.

The Prism P/Invoke declarations were compared with the pinned v0.18.3 public C header. This can detect declaration mismatches; it cannot prove the behavior of every native driver, screen reader, voice or braille display.

Native DLL crashes and blocked driver calls cannot always be recovered in managed code. Shutdown therefore has a bounded wait and avoids freeing a context from a different thread. A failed speech batch is logged and dropped; later requests can continue, but the failed text is not automatically replayed.

Some calibration callbacks still observe native state from FMOD callbacks. Existing guards contain managed exceptions, but static review cannot prove every cross-thread timing behavior. Changing that scheduling without human play testing could affect calibration, so it remains a specific follow-up area.

The guide remains a lightweight reader for the supplied HTML documents rather than a general browser. Its new limits intentionally reject unusually large or deeply nested documents and fall back safely. Installer cleanup can remain incomplete when Windows denies access to a profile; the retained launcher and checkpoint permit a later retry.

The performance changes remove identifiable repeated work and allocations. No measured frame-rate, latency or memory improvement is claimed. Human checks before release should exercise native and custom rebinding, held/released opening inputs, first-run welcome, all guide tables, score-before-menu ordering, OneCore/SAPI switches and background behavior. Installer abort, interrupted recovery, shared-loader preservation and preference-cleanup retry also need checks on a disposable test installation.

No issue found by this review is an assurance that the project is free of defects. This build is a release-preparation candidate, not the 1.0 public release.

Editable configuration uses fingerprints and atomic replacement, but the last comparison and rename are not an operating-system compare-and-swap: a noncooperating editor can write in that narrow interval. Hard termination can leave a unique temporary file; uninstall only removes validated owned names. Native game/Steam preference persistence can partly write before throwing and has no shared transaction API.

Legacy manual installations have no durable ownership ledger. Their removal can only claim known mod files and safely identified dependencies, and cleanup warnings can be retried in the open installer. The retained Windows entry/checkpoint route applies to installer-managed copies. Missing backups, denied profile access, unavailable drives and conservative shared-loader detection can require a later retry; they are reported rather than silently deleting uncertain files.

Input-asset cleanup is intended for application shutdown on Unity's thread. A future hot-unload path with a continuing game must remove cloned rows and prompt references before destroying their referenced mod input assets. Native driver calls, multi-controller capture ordering and calibration callbacks still need human runtime checks.

All six Python authoring scripts passed syntax compilation with py_compile. PowerShell's AST parser reported zero syntax errors for uninstall.ps1 and prepare_prism.ps1. These checks did not execute script functionality, download dependencies or exercise installation/removal.

The portable SDK is prepared before the file transaction. Caught cancellation removes its staging directory, but a power loss during extraction can leave that unique directory behind. An ordinary uninstall intentionally retains the SDK. If a new installer owns the cleanup mutex when an old cleanup helper wakes, the helper preserves the state folder; its completed-uninstall records allow a later cleanup retry.
